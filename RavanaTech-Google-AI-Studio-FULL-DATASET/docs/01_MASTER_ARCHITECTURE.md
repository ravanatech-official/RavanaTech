# 01 — Master Architecture

## 1. North-star experience

The system is optimized for **time-to-value**, not page depth.

A visitor can arrive with any of these conditions:
- technical expert or no technical knowledge;
- existing business or only an idea;
- Sri Lanka or another country;
- clear requirement or “I don't know what I need”;
- browsing, comparing, or ready to contact.

The UI must never expose that complexity. It presents one clear decision at a time.

## 2. Five first intents

1. **I need a new website / web app**
2. **I want to improve an existing website**
3. **I want to see what Ravana Tech can build**
4. **I need help deciding what I actually need**
5. **I want to talk about a project / quotation**

These are user intents, not technical categories. The fifth is intentionally contact-oriented; it does not force a long form.

## 3. The 5×5 rule

Every active journey presents up to five choices. Every choice leads to another small decision, a useful proof item, or completion.

The flow is not a rigid five-question survey. The state machine chooses the next node from the visitor's answers.

```text
Intent 1 → choose any 1..5 → next 1..5 → next 1..5 → next 1..5 → outcome
Intent 2 → choose any 1..5 → next 1..5 → next 1..5 → next 1..5 → outcome
Intent 3 → choose any 1..5 → next 1..5 → next 1..5 → next 1..5 → outcome
Intent 4 → choose any 1..5 → next 1..5 → next 1..5 → next 1..5 → outcome
Intent 5 → choose any 1..5 → next 1..5 → next 1..5 → next 1..5 → outcome
```

A journey may finish earlier when the visitor has enough information. Do not manufacture extra questions merely to reach five steps.

## 4. Interaction contract

At every step:
- Founder avatar says one short sentence.
- The question is visible in plain language.
- Five large options appear.
- Each option has a one-line explanation.
- Only one primary next action is visually dominant.
- Back/change-answer is always available.
- “Not sure” is always available where uncertainty is plausible.
- A small progress indicator says what has already been understood.
- No technical jargon is required.

## 5. Trust-building rhythm

Every interaction should follow:

```text
You said X
→ I understood X
→ Based on X, here is the next simple choice
→ Here is useful proof/value
→ You can continue or change it
```

This is how the visitor experiences the feeling of meeting the founder before the real meeting.

## 6. No scroll hunting

Do not make the visitor search through 20 sections. The receptionist routes them to the exact relevant section, service, demo, FAQ, or contact action. Normal site navigation remains available for independent browsing.
